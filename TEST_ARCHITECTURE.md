# Test Architecture: YAML vs Generated Code

## Quick Answer

**Tests are run on the GENERATED C/HEADER CODE, but they VALIDATE against the YAML specifications.**

Think of it this way:

```
YAML (Input)
   ↓
[BSP Generator]
   ↓
Generated C Code (gio.c, sci.c, etc.)
   ↓
[Validation Test Generator]
   ↓
Unit Tests (gio_test.c, sci_test.c, etc.)
   ↓
[Test Execution]
   ├─ Mock the C code's register accesses
   └─ Verify they match what YAML specified
```

---

## Two-Layer Testing

### Layer 1: Generation Validation (Current)

This happens DURING BSP generation:

```
YAML Input
   ↓
Prompt with YAML embedded
   ↓
LLM generates C code
   ↓
FACTS MIRROR extracted (all hardware constants)
   ↓
Constant values compared to YAML
   ↓
✅ or ❌ Generation validated
```

**What's checked**:

- All register addresses used are in FACTS MIRROR
- FACTS MIRROR values came from YAML
- No made-up hardware values

**Current status**: ✅ Partially automated (FACTS MIRROR extraction)

---

### Layer 2: Code Validation (What validation_prompt.py does)

This happens AFTER BSP generation:

```
Generated C Files (gio.c, gio.h, sci.c, sci.h, etc.)
   ↓
[validation_prompt.py creates test prompts]
   ↓
LLM generates unit tests
   ↓
Tests mock register access
   ↓
Tests verify behavior against YAML spec
```

**What gets tested**:

- ✅ Each function does what its documentation says
- ✅ Register writes match YAML expectations
- ✅ Initialization sequences are complete
- ✅ API functions have correct parameters
- ✅ Cross-file consistency (all drivers work together)
- ✅ Startup sequence works (assembly → C → main)
- ✅ Memory layout matches linker script

## Concrete Example: GPIO Driver Testing

### The YAML (Input)

**app/yaml_in/soc.yaml**:

```yaml
peripherals:
  - name: GIO
    type: gpio
    instance: 1
    regs_ref: GIO
    x-ext:
      init:
        - reg: "GIO.GCR0"
          op: "write"
          value: "0x00000001"
```

**app/yaml_in/regs.yaml**:

```yaml
peripherals:
  GIO:
    base_address: "0xFFF7BC00"
    registers:
      GCR0:
        offset: "0x00"
      DOUT_A:
        offset: "0x3C"
      DIN_A:
        offset: "0x38"
      DIR_A:
        offset: "0x34"
```

### The Generated Code (Step 1 Output)

**bsp_gen/output_20260127_133938/gio.h**:

```c
/**
 * @brief Set GPIO pin direction
 * @ingroup BSP_GIO
 */
void gio_set_dir(uint32_t port, uint32_t pin, uint32_t output);

/**
 * @brief Set GPIO pin HIGH
 * @ingroup BSP_GIO
 */
void gio_set(uint32_t port, uint32_t pin);

/**
 * @brief Read GPIO pin state
 * @ingroup BSP_GIO
 */
uint32_t gio_read(uint32_t port, uint32_t pin);
```

**bsp_gen/output_20260127_133938/gio.c**:

```c
#define GIO_BASE 0xFFF7BC00u
#define GIO_DIR_A_OFFSET 0x34u
#define GIO_DOUT_A_OFFSET 0x3Cu
#define GIO_DIN_A_OFFSET 0x38u

void gio_set_dir(uint32_t port, uint32_t pin, uint32_t output)
{
    uint32_t addr;

    // [prov] regs.yaml:GIO.DIR_A
    addr = GIO_BASE + GIO_DIR_A_OFFSET;
    if (output) {
        REG32(addr) |= (1u << pin);
    } else {
        REG32(addr) &= ~(1u << pin);
    }
}

void gio_set(uint32_t port, uint32_t pin)
{
    uint32_t addr;

    // [prov] regs.yaml:GIO.DOUT_A
    addr = GIO_BASE + GIO_DOUT_A_OFFSET;
    REG32(addr) |= (1u << pin);
}

uint32_t gio_read(uint32_t port, uint32_t pin)
{
    uint32_t addr, val;

    // [prov] regs.yaml:GIO.DIN_A
    addr = GIO_BASE + GIO_DIN_A_OFFSET;
    val = REG32(addr);
    return (val >> pin) & 1u;
}
```

### The Validation Tests (Step 2 Output)

**bsp_gen/output_20260127_133938/tests/gio_test.c** (generated by LLM):

```c
#include <unity.h>
#include <stdint.h>
#include <string.h>
#include "gio.h"

// ============= MOCK HARDWARE =============
// Simulates the actual hardware registers
#define GIO_NUM_REGISTERS 128
static volatile uint32_t mock_registers[GIO_NUM_REGISTERS];

// Override REG32 macro to use our mock
#undef REG32
#define REG32(addr) mock_registers[((addr - GIO_BASE) / 4)]

// ============= TEST SETUP/TEARDOWN =============
void setUp(void)
{
    // Clear all mock registers before each test
    memset((void*)mock_registers, 0, sizeof(mock_registers));
}

void tearDown(void)
{
    // Cleanup after each test (if needed)
}

// ============= TEST CASES =============

// Test 1: Verify gio_set() writes to correct DOUT_A register
void test_gio_set_writes_to_correct_register(void)
{
    // YAML specifies: GIO base = 0xFFF7BC00, DOUT_A offset = 0x3C
    // Expected: gio_set(GIO_PORT_A, 3) should set bit 3 of register at 0xFFF7BC3C

    gio_set(GIO_PORT_A, 3);

    // Check that the correct register was written
    uint32_t expected_addr_offset = (0xFFF7BC3C - GIO_BASE) / 4;
    uint32_t expected_value = (1u << 3);

    TEST_ASSERT_EQUAL_HEX32(expected_value, mock_registers[expected_addr_offset]);
}

// Test 2: Verify gio_set_dir() modifies DIR_A register
void test_gio_set_dir_output_sets_bit(void)
{
    // YAML specifies: DIR_A offset = 0x34
    // Expected: gio_set_dir(GIO_PORT_A, 5, 1) should set bit 5

    gio_set_dir(GIO_PORT_A, 5, 1);  // Pin 5 as output

    uint32_t expected_addr_offset = (0xFFF7BC34 - GIO_BASE) / 4;
    uint32_t expected_value = (1u << 5);

    TEST_ASSERT_EQUAL_HEX32(expected_value, mock_registers[expected_addr_offset]);
}

// Test 3: Verify gio_read() reads from correct DIN_A register
void test_gio_read_reads_from_correct_register(void)
{
    // YAML specifies: DIN_A offset = 0x38
    // Setup: Put a known value in DIN_A
    uint32_t din_offset = (0xFFF7BC38 - GIO_BASE) / 4;
    mock_registers[din_offset] = 0x00000008;  // Bit 3 set

    // Call gio_read
    uint32_t result = gio_read(GIO_PORT_A, 3);

    // Verify it read bit 3
    TEST_ASSERT_EQUAL_UINT32(1, result);
}

// Test 4: Cross-verify addresses match FACTS MIRROR
void test_gio_addresses_match_yaml_specification(void)
{
    // FACTS MIRROR values (extracted from YAML):
    // GIO_BASE = 0xFFF7BC00
    // GIO_DIR_A_OFFSET = 0x34
    // GIO_DOUT_A_OFFSET = 0x3C
    // GIO_DIN_A_OFFSET = 0x38

    TEST_ASSERT_EQUAL_HEX32(0xFFF7BC00u, GIO_BASE);
    TEST_ASSERT_EQUAL_HEX32(0x34u, GIO_DIR_A_OFFSET);
    TEST_ASSERT_EQUAL_HEX32(0x3Cu, GIO_DOUT_A_OFFSET);
    TEST_ASSERT_EQUAL_HEX32(0x38u, GIO_DIN_A_OFFSET);
}

// ============= MAIN TEST RUNNER =============
int main(void)
{
    UNITY_BEGIN();

    RUN_TEST(test_gio_set_writes_to_correct_register);
    RUN_TEST(test_gio_set_dir_output_sets_bit);
    RUN_TEST(test_gio_read_reads_from_correct_register);
    RUN_TEST(test_gio_addresses_match_yaml_specification);

    return UNITY_END();
}
```

## The Three Levels of Validation

### Level 1: FACTS MIRROR (Current ✅)

**What**: Extract all numeric values from generated code  
**Where**: `_artifacts/llm_preamble_*.txt`  
**Tests**: Manual verification against datasheet

```
YAML Input
  ↓
[BSP Gen]
  ↓
Generated Code
  ↓
FACTS MIRROR extracted
  ↓
✅ Compare to YAML
```

### Level 2: Unit Tests (What validation_prompt.py creates)

**What**: Test each driver function individually  
**Where**: `tests/gio_test.c`, `tests/sci_test.c`, etc.  
**Tests**: Mock register access, verify correct addresses/values

```
Generated C Code
  ↓
[Test Generator]
  ↓
Unit Tests (with mocks)
  ↓
[Test Execution]
  ├─ Mock registers
  ├─ Call gio_set()
  └─ ✅ Verify register write correct
```

### Level 3: Integration Tests (Advanced)

**What**: Test startup sequence, cross-file behavior  
**Where**: `tests/startup_integration_test.c`, `tests/cross_validation_test.c`  
**Tests**: Verify .data copy, .bss zeroing, system_init() calls

```
Entry Code + System Init + Linker Script
  ↓
[Integration Test Generator]
  ↓
Integration Tests
  ↓
[Test Execution]
  ├─ Verify data section copy
  ├─ Verify BSS zeroing
  ├─ ✅ Verify system_init called
  └─ ✅ Verify startup sequence correct
```

## Current State vs Proposed State

### Current (Today)

```
✅ YAML Input
   ↓
✅ BSP Generator (LLM creates C code)
   ↓
✅ FACTS MIRROR extracted
   ↓
🔄 Manual validation of FACTS MIRROR against YAML
   ↓
Generated Code (✅ assumed correct)
```

**Result**: You get the BSP, but validation is manual

### Proposed (With validation_prompt.py)

```
✅ YAML Input
   ↓
✅ BSP Generator (LLM creates C code)
   ↓
✅ FACTS MIRROR extracted
   ↓
✅ Validation Test Generator (LLM creates unit tests)
   ↓
✅ Test Execution (mock registers, verify behavior)
   ↓
Generated Code (✅ automatically validated)
```

**Result**: Fully automated validation, comprehensive test coverage

## What Gets Tested

### Per-Peripheral Tests

- ✅ All register addresses match YAML
- ✅ All offsets are correct
- ✅ API functions perform correct register operations
- ✅ Bit manipulation is correct (set, clear, toggle, read)
- ✅ Initialization sequences follow YAML spec

### Integration Tests

- ✅ Startup assembly loads stack correctly
- ✅ Entry.c copies .data from FLASH to RAM
- ✅ Entry.c zeros .bss section
- ✅ system_init() called before main()
- ✅ All peripherals initialized in correct order
- ✅ Linker script defines correct memory regions

### Cross-File Tests

- ✅ No macro name conflicts
- ✅ No register address conflicts
- ✅ All defined symbols used consistently
- ✅ No missing dependencies between files
- ✅ Startup sequence flows correctly end-to-end

## Summary

**Tests run ON**: Generated C code (gio.c, sci.c, etc.)  
**Tests validate AGAINST**: YAML specifications  
**How**: Mock hardware registers, verify register operations  
**Result**: Automated assurance that generated code matches hardware spec

Think of it as:

- **YAML** = "What the hardware should do"
- **Generated C** = "Code that controls the hardware"
- **Tests** = "Verify the code actually does what the YAML specifies"
